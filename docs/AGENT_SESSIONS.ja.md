# ほかの AI に頼んだ仕事の見守り（Claude Code）

Agent Orchestration の第 1 段（2026-10-28）。Claude Code のセッションが「いまどうなっているか」を Genie が知り、
Mac の作業一覧（「ほかの AI に頼んだ仕事」、予約の下）で一覧できるようにする。画面は見ない。Claude Code の hooks が出来事を手元の Genie へ送る。

```
Claude Code ──hooks（async）──▶ scripts/claude-code-hook.sh ──127.0.0.1──▶ POST /v1/agent-events/claude-code
                                                                         └▶ agent_sessions（セッションごとに 1 行）
作業一覧 ◀── GET /v1/agent-sessions（attention: needs_user / stalled_suspected / working / idle / paused / ended）
```

## つなぐ・外す

```sh
node scripts/claude-code-hooks.mjs install     # 鍵を発行してキーチェーンへ、~/.claude/settings.json に hooks を足す
node scripts/claude-code-hooks.mjs status      # hooks の数・鍵の有無・最後に届いた時刻（鍵の値は出さない）
node scripts/claude-code-hooks.mjs uninstall   # hooks を外し、鍵を取り消してキーチェーンから消す
```

- プレビュー（`pnpm preview`）が動いているときに使う。手元の利用者（Mac と同じ人）として鍵を発行する。
- settings.json は Genie の hooks を**足すだけ・外すだけ**。ほかの hooks・設定は残し、書く前に `.bak` を置く。
- hooks はすべて `async`。Genie が止まっていても Claude Code は待たない・何も表示しない（送り口は常に 0 で終わる）。
- 送り先は `http://127.0.0.1:<番号>` / `http://localhost:<番号>` だけ。それ以外は鍵を読む前に断る。
- 鍵はキーチェーンの `com.astra.agent-hook`（アカウントは gateway の URL）。`/usr/bin/security` が作るので、
  hooks が読むときにパスワードを聞かれない。Genie.app の鍵（`com.astra.mac`）とは分けてある
  （出来事のたびに Genie.app を起こさないため）。この鍵でできるのは、自分のセッションの状態を送ることだけ。

## 状態の決め方

| 出来事                                 | state                      | 備考                                                                         |
| -------------------------------------- | -------------------------- | ---------------------------------------------------------------------------- |
| SessionStart                           | idle                       | 頼みを待っている                                                             |
| UserPromptSubmit・PostToolUse など     | working                    | 最初の頼みの頭（1 行・80 字・鍵らしい文字列は伏せる）を名前にする            |
| PermissionRequest・承認の Notification | waiting_user（permission） | 一覧では needs_user                                                          |
| 入力待ちの Notification・Elicitation   | waiting_user（input）      |                                                                              |
| Stop                                   | idle                       | **仕事が終わった、ではない。**応答が終わっただけ。完了は成果物で別に確かめる |
| StopFailure                            | error                      | 一覧では needs_user                                                          |
| SessionEnd                             | ended                      | 1 日たつと一覧から消える                                                     |

- Stop の直後 3 秒以内に遅れて届いた道具の出来事では working に戻さない（hooks は裏で走るので順が入れ替わる）。
- `working` のまま 15 分届かなければ `stalled_suspected`（confidence は `inferred`）。仮の値。
- 本人が止めた（`PATCH /v1/agent-sessions/:id {"user_policy":"paused_by_user"}`）セッションは、
  何が届いても `paused`。待ち・停滞として知らせない。`watch` で戻す。

## 残すもの・残さないもの

残す: セッション ID・フォルダの名前（フルパスではない）・頼みの頭・状態・待ちの理由・時刻。
残さない: 道具の入出力・頼みの全文・応答の本文・会話の記録の場所（transcript_path）。
台帳の印（`agent_session_marks`）も種類と時刻だけで、頼みの文・コマンド・変えたファイルの名前は残さない。

## 知らせ（第 3 段、2026-10-29）

見回り（`services/api-gateway/src/agent-session-watch.ts`）が 15 秒ごとに、見る時刻（`check_after`）が来たセッションだけを見る。
見る時刻は出来事が届くたびに決め直す。

| いま                       | 知らせる時              | Mac の通知の題                           |
| -------------------------- | ----------------------- | ---------------------------------------- |
| 承認待ち                   | その待ちが 1 分続いたら | Claude Code が承認を待っています         |
| 入力待ち                   | 同上                    | Claude Code があなたの返事を待っています |
| 失敗で止まった             | 同上                    | Claude Code がうまくいかずに止まりました |
| 作業中のまま 15 分届かない | 15 分たったら           | Claude Code が止まっているかもしれません |

- 同じ待ちは 1 回だけ（待ちの始まりの時刻で見分ける。同じ待ちに出来事が重ねて届いても待ちの始まりは動かさない）。
  ターミナルの前で 1 分以内に答えた承認は知らせない。応答を終えた（Stop）だけのセッションは知らせない。
- 本人が止めたセッションは知らせない。見守りに戻したとき、まだ待っていれば知らせる。
- 知らせる先: Mac の通知（`user_notices` の `agent_session` → `NoticeInbox`。押すと作業一覧が開く）と、
  LINE をつないでいれば本人の LINE。**LINE への文には頼みの頭を載せない**（フォルダの名前と状態だけ。
  例「🔔 Claude Code（genie）が承認を待っています。Mac のターミナルで確かめてください。」）。Mac の通知には載せる。
- **見守りから Claude Code には何も送らない（促さない）。**ターミナルに文字を打ち込むこともしない（本人の画面を操作しない）。
  承認だけは、下の「LINE からの承認」で本人が答えたものを hooks が取りに来て返す。
  承認のカードを LINE に出しているあいだは、「ターミナルで確かめてください」を重ねて送らない。

## LINE からの承認（2026-10-30、`services/api-gateway/src/agent-approvals.ts`・`agent-approval-policy.ts`）

Claude Code が許可を求めると（PermissionRequest）、本人の LINE の 1:1 にカードが届く。
「承認の要求を LINE へ転送する」のではなく、**何の作業の・何の操作か・リスク・承認の範囲・実行の結果**をひとつにする。
答えで**元のセッションがそのまま続く**。Mac の前にいなくてよい。

    Claude Code ─ PermissionRequest（同期の hooks: scripts/claude-code-permission.sh）
      → POST /v1/agent-approvals/claude-code
          本人の継続許可（承認ルール）に当たる → 200 とその場の許可（カードは出さない。記録は残す）
          当たらない → 本人の LINE にカード（201）。hooks は POST /v1/agent-approvals/:id/wait で答えを取りに来る
      → 答えを標準出力に出す（承認 = allow、拒否 = deny、指示 = deny と指示の文）

### カード

| 行 | 中身 | 取れないとき |
| --- | --- | --- |
| 見出し | 「Claude Codeが承認を待っています（#番号）」と何をするか。番号でカードどうしを見分ける | — |
| プロジェクト | git の根のフォルダ名と（ブランチ）。gateway が手元の git に聞く（`project-info.ts`） | 未確認 |
| 作業 | そのセッションの最初の頼みの頭（1 行・80 字・鍵らしい文字列は伏せる） | 未確認 |
| タスク | Genie の仕事に結び付いていればその名前 | タスク未紐付け（推して埋めない） |
| 実行する場所 | プロジェクトからの道（ホームは ~） | 未確認 |
| 操作の種類・リスク | `agent-approval-policy.ts` の分け方（低・中・高）。毎回確認の操作は理由も | — |
| 中身 | コマンド・ファイル（プロジェクトからの道）・消す/入れる文の頭・アドレス。**鍵・パスワード・トークンは伏せる** | — |

ボタン: **今回だけ承認** / **拒否** / **指示を添える** / **このセッションで同種を許可** / **このプロジェクトで常に許可**
（後の 2 つは、継続許可にしてよい種類のときだけ出す）。

### 継続許可（承認ルール）

- 継続許可は**コマンド名だけで決めない**。操作の種類（読むだけ・テストやビルド・プロジェクト内にファイルを作る・
  プロジェクト内のファイルを書き換える・パッケージを入れる・ウェブを読む〔ホストごと〕・MCP の道具〔名前ごと〕・
  それ以外のコマンド〔同じ文だけ〕）・対象のパス（すべてプロジェクトの中か）・プロジェクト（セッション）で決める。
- **問いが来るたびに評価し直す**（ルールがあっても、プロジェクトの外のパス・別の種類なら聞く）。
- **継続許可にしないもの（毎回聞く）:** 秘密（.env・鍵・認証情報・Keychain）/ 外への送信（git push・publish・
  データを送る curl・scp・ssh など）/ 本番・デプロイ / 壊す操作（rm -r・reset --hard・強制 push など）/
  管理者の権限・権限の一括変更 / 決済 / Claude Code の設定・hooks / プロジェクトの外。
  継続許可のボタンを出さず、押されても gateway で断る（`not_ruleable`）。
- セッションのルールは、そのセッションが終わったら（SessionEnd）使わない。
- 一覧・取り消し: LINE で「承認ルール」「承認ルール 1 を取り消して」「承認ルールを全部取り消して」。
  仕事のホーム（LIFF）の「Claude Code の承認ルール」でも一覧・取り消し・最近の承認の記録を見られる
  （このページで変えられるのは取り消しだけ。LINE の中継が通すのも、その取り消しの POST だけ）。
- 「すべてのプロジェクトで安全な同種操作を許可」は、まだ無い（いまはセッションとプロジェクトだけ）。

### 経過と記録

- 1 件ごとに 受け付けた（`decided_at`）→ Claude Code に渡した（`delivered_at`。hooks が答えを受け取った）→
  実行を確かめた（`result`: 同じ入力の PostToolUse = executed / PostToolUseFailure = failed）を分けて残す。
  **押しただけで「実行した」とは言わない。**LINE で答えたものは、実行を確かめたら「✓ Claude Code が実行しました」と知らせる。
- 承認ルールで自動で許可したものも `agent_approvals` に `auto_allowed` とルールの id で残す（監査）。
  ルールには作った時刻・取り消した時刻・使った回数・最後に使った時刻を残す。
- 残すのは、いつ・どの道具が・どの種類とリスクで・どう答えられたか・指示を添えたか（文は残さない）・入力のハッシュ・
  Claude Code の頼みの ID（`prompt_id`）。コマンドやファイルの中身は残さない（カードの写しは gateway のメモリだけ）。

### 守ること

- **Genie は自分の判断では承認しない。**答えるのは本人のボタン・文と、本人が作った承認ルールだけ。
- Mac の画面にも同じ問いが出ていて、**先に答えたほうが通る**。Mac で答えて実行されたら（同じ入力の PostToolUse）、
  または次の頼み・応答の終わり・セッションの終わりが来たら、カードを取り下げる（押すと「Mac で答え済みです」）。
- ボタンは署名つき（`c1.<承認>.<連携>.<A|R|I|S|P>.<期限>.<署名>`、鍵は `channel-action-secret`）。
  押した人がその連携の本人か・まだ待っているか・期限内かを確かめ、**1 回だけ**通す（同時に押しても 1 回）。
  入力が変われば別の承認（古いカードのボタンは通らない）。
- LINE をつないでいない・Genie が止まっている・期限（9 分）が来た … hooks は**何も出さずに終わる**。
  Mac の問いがそのまま残る。送り直し待ち（LINE に一時的につながらない）のカードは、送り直されるまで待ちを保つ。
- 本人が見守りを止めたセッションは LINE に出さない（承認ルールには従う）。
- つなぐ: `node scripts/claude-code-hooks.mjs install`（PermissionRequest に同期の hooks を 1 つ足す。待ちは 600 秒まで）。

実機で確かめたこと（Claude Code 2.1.312〜314、手元のプレビュー）:
hooks が待つ間も Mac に問いが出る / hooks の allow で問いが閉じて実行され、同じセッションが続く /
deny と文で、Claude Code はその文を読んで続ける / 何も返さなければ Mac の問いが残る /
Mac で先に答えると、そちらで進む（hooks は自分の期限まで止まらないので、gateway が取り下げる） /
本物の LINE のカードの「承認」で、元のセッションが続いた（3 回）。

2026-10-30 12:19 の「承認」が届かなかった件: Mac の再起動でトンネル（cloudflared の一時 URL）が変わり、
LINE の Webhook URL が古いままだったため、押した操作が Genie に届かなかった（12:17〜12:27 に届いたのは
Webhook の疎通テストだけ）。12:27 のカードは送り直しではなく別の要求（別の承認の id）。
再起動のあとは、トンネルを立て直したら Webhook URL も直す（docs/LINE_SETUP.ja.md）。

## 確かめ（2026-10-29）

応答を終えた（Stop）だけでは「完了」と言わない。hooks の道具の出来事から、変更とテストの結果を覚える
（`check_state`。コマンドの文は種類を見るためだけに読み、残さない）。

| 出来事                                                       | check_state                                     |
| ------------------------------------------------------------ | ----------------------------------------------- |
| Edit・Write・MultiEdit・NotebookEdit が通った                | changed（変えたが、まだテストで確かめていない） |
| テストらしい Bash（vitest・pytest・swift test など）が通った | passed                                          |
| テストらしい Bash が失敗した（PostToolUseFailure）           | failed                                          |

一覧・まとめでは、応答を終えたセッションに「テストが通っています / 変更をまだテストで確かめていません /
最後のテストが失敗しています（確かめてほしいもの）」を添える。テストを走らせたかどうかしか見ていないので、
**テストが仕様を満たしているかは分からない**（通ったことは確かめ済みの必要条件で、十分条件ではない）。

作業中のまま 2 時間何も届かないセッションは `unknown`（「いまの状態は分かりません」）。ターミナルを閉じた・
Mac が眠ったなどで、終わったとも止まったとも言わない。

## 仕事の見通し・保留・続き（2026-10-29、`services/api-gateway/src/work-desk.ts`・`work-holds.ts`）

| 言い方                                     | すること                                                                                                        |
| ------------------------------------------ | --------------------------------------------------------------------------------------------------------------- |
| 今の作業どうなってる？／今日の作業を教えて | Genie の仕事・Claude Code・予約・保留・続きをまとめて答える。返事が要るものを先に、推した状態は推したと言う     |
| デザインは来週まで保留。理由は仕様待ち     | 保留を作る。名前に当たる Claude Code のセッション（フォルダ名・頼みの頭）は知らせを止め（`held`）、予約は止める |
| デザインの保留を解除して                   | 解除する。保留で静かにしたセッションは見守りに戻し、保留で止めた予約は戻す                                      |
| 止まっているものを全部進めて               | **何も勝手に動かさない。**保留は進めないと言い、承認・返事など本人の手が要るものを挙げる                        |
| これが終わったら統合テストを実行して       | いま動いている本人の仕事が COMPLETED になったときだけ 1 回始める（失敗・取り消しなら始めずに知らせる）          |

- 保留は勝手に解除しない。保留の日が来たら 1 回だけ「再開しますか」と知らせる（Mac の通知 `work_hold` と LINE）。
- 保留のあとに始まった同じ名前のセッションも、届いた時点から静か。「この案件は保留」のように名前が無いときは、
  どれかを訊き返す（いま開いているフォルダ名を挙げる）。
- 続きの頼みは、保留中の名前に触れるものは受けない。受けたあとに保留になったら、始める時に止めて知らせる。
  同じ頼みから仕事を二度作らない（頼みの id を発話の id にして、`turn:<id>` の冪等キーに乗せる）。
- 作業一覧の先頭に件数と返事が要るものの札（`GET /v1/work/overview`、`WorkOverviewCard`。DESIGN.md §8.5）。

## 仕事の台帳（2026-10-29、`services/api-gateway/src/work-ledger.ts`）

1 つの仕事について、依頼・完了条件・経過・本人の判断・成果物・確かめ・次に要ることを 1 か所に並べる。
仕事は Genie の仕事（`tasks`）か Claude Code のセッション。Genie の仕事の依頼・途中の指示・承認・成果物は
既存の表（`tasks`・`task_instructions`・`approvals`・`artifacts`）を読むだけで、写しは作らない。

| 言い方                                              | すること                                                                                                     |
| --------------------------------------------------- | ------------------------------------------------------------------------------------------------------------ |
| genie の完了条件はテストが通ること、LINE に届くこと | 条件を覚える（`work_criteria`）。テストを含む条件は Claude Code のテストの結果で、ほかは本人の言葉で確かめる |
| genie の完了条件は確かめた                          | 自動で確かめられない条件を、本人が確かめたものとして記録する（テストの条件は言葉では満たさない）             |
| genie はどこまで進んだ？／請求書の経緯を教えて      | 台帳を話し言葉で答える（Claude Code の頼みの頭は出さない）                                                   |

- `GET /v1/work/ledger?session=<id>` / `?task=<id>`: 台帳そのもの（Mac の画面向け。頼みの頭も載せる）。本人のものだけ。
- Claude Code のセッションの経過は `agent_session_marks`（依頼・追加の指示・承認待ち・返事待ち・変更・テストの成否・
  応答の終わり・止まった・終わった）。同じ待ちが重ねて届いても 1 回、変更は確かめ済みから変わったときだけ、
  機械の知らせ（`<task-notification>` など）は指示に数えない。
- 満たしていない・確かめていない完了条件があるうちは「終わった」と言わない。テストの条件は、変えたあとテストを
  走らせていなければ、前に通っていても満たしたとは言わない。
- 「今の作業はどこまで進んだ？」のように名前が無いときは、全体の見通しの答えに任せる。

## 仕事のホーム（2026-10-29、`services/api-gateway/src/work-home.ts`・`work-page.ts`）

LINE で「仕事のホームを開いて」「マイページ」と送ると、本人だけのリンク（30 日・読むだけ）を返す。
ページは、あなたの確認が必要なもの（無ければ「ありません」と言い切る）→ 件数（動いている・確認が必要・今日終わった）
→ 仕事の一覧（確認が必要 → 動いている → 静か → 終わった）→ 保留 → 続き の順。行を開くと、その仕事の台帳
（次に要ること・確かめ・完了条件・経過・判断・成果物）。

- 公開の場所（トンネル）を通るので、Claude Code の頼みの頭は出さない。変える道は無い（会話で変える）。
- LINE の中では計画ボードの LIFF の入口を `/w/<リンク>` で使う（docs/LINE_GROUPS.ja.md）。
- 公開の場所（`GENIE_PUBLIC_URL`）も LIFF も無ければリンクを作らず、そう言う。
- Slack・LINE の「終わりました」の知らせにも、頼んだ本人のホームのリンクを付ける（本文を送る設定のときは本文が先）。
  リンクを作れなければ、これまでどおり Mac の作業一覧へ案内する。
- LINE で「今の作業どうなってる？」と聞くと、答えの文に見通しのカード（`genie.work/v1`）を添える。並びはホームと同じ
  （確認が必要なもの 3 件まで → 件数 → 仕事 5 件まで → 「仕事のホームを開く」）。Slack・通知は文だけ。

## 画面操作の引き継ぎ（2026-10-29）

「ここから自分で操作する」→ Mac（`ComputerHandoff`）が、いま動いている画面操作の印（`background-<id>.json`）の隣に
`.handoff` と `.interrupted` を置く。送りかけの入力はその場で失効し、helper は印がある間は再開を断る（`human_handoff`）。
worker は回数に数えずに待ち、「続きお願い」で印が消えたら、世代を進めて画面を撮り直してから続ける（古い座標は使わない）。
走行の上限（既定 5 分）が来たら「引き継いだまま終えた」と言って止める（入力は送っていない）。
言い方は端末の中だけで受ける（gateway・モデルは通さない）。「続けて」のような短い語は、本人の番のときだけ受ける。

## まだ無いもの

- 差分の中身・テストの網羅での確かめ（いまはテストを走らせて通ったかだけ）
- 担当が替わったときのつなぎ（Claude Code の別のセッション・Codex へ移っても、同じ仕事の台帳に載せる）。
  いまはセッション 1 つ・Genie の仕事 1 つごとの台帳
- 台帳を見る Mac の画面（いまは LINE から開く仕事のホームと話し言葉）
- Codex のセッション（知らせを取る口があるかをまだ調べていない）
- ChatGPT・Muse など、ほかの AI（状態を取る公式の口が無い。作るなら画面から観測し、観測時刻と確度を付ける）
- 優先度・期限での並べ替えと、空き時間の提案（いまは返事が要るものを先に出すだけ）

## ブラウザの引き継ぎ（2026-10-30）

「<URL> を読んで」で開いたページがログインの壁（パスワードの欄）だったら、Genie 専用のブラウザを閉じずに残し、
LINE に「ログインだけお願いします」とリンク（15 分・本人だけ。LIFF の入口 `/h/<リンク>`）を送る。
本人はスマホでそのブラウザの画面をその場で見て、押す・スクロール・文字・Enter で操作する。パスワードの欄が消えたら
（または「Genie に戻す」で）Genie が頼まれたページを読み直して答える。ログインは専用のプロファイルに残るので、次からは Genie だけで読める。

- 端末から gateway へは画面を送り、本人の操作は端末が取りに行く（gateway から端末へは繋がない）。画面・入力はメモリで取り次ぐだけ
- Genie は引き継ぎの間、自分では入力しない。決済・送信・削除はいつもどおり別の承認が要る
- step の上限（5 分）の中に収めるため、本人を待つのは 3 分。時間切れでもログインが済んでいれば、頼み直すと読める
- まだ無いもの: 押す・入れるを Genie が進める操作役（予約など）と、それがつまずいたときの同じ引き継ぎ。LINE の知らせへの画面の画像の添付

## エージェントの仕事（Genie が引き受けて進める）

本人の方針（2026-10-30）: タスク管理を本人にさせず、Genie が引き受ける。OSS は入れず、既存の見守り・LINE 承認の上に足す。

- **2 種類の仕事:** `managed`（Genie が起動して進める）と `observed`（本人が直接始めたセッションの取り込み。**読むだけ**で、再開・停止・指示はしない）。
- **発見:** Claude Code は登録済みの hooks、Codex は `~/.codex/sessions` の記録を読む（種類・セッション・フォルダ・最初の頼みの頭だけ）。OpenCode の自動発見と、ブラウザ担当の接続はまだ無い。
- **共通の窓口:** `services/api-gateway/src/agent-adapters.ts`。Claude Code は `claude -p`、Codex は `codex exec --json`（Codex の起動は実機で未確認）。Muse などは製品が決まったらここに足す。
- **完了:** エージェントの言葉では決めない。完了条件（コマンド・成果物・本人の確認）を Genie が確かめる。条件のない仕事は作らない。
- **本人を待つ:** 失敗にしない。承認を待つあいだは実行時間に数えない（`human_wait_ms`）。カードの期限が切れたら作業を止めて `waiting_human` で待ち、「仕事 N を再開」で同じセッションの続きから、残りの予算で進める。古いカードは使わず、操作が要れば改めて聞く。後の仕事は `waiting_dependency` で待ち、先の仕事が終わったら自動で始まる。再開できるのは仕事を作ってから 7 日（`max_lifetime_hours`）。
- **止める:** 再試行 3 回・同じ失敗 2 回・時間・手数・費用・1 日の費用（`GENIE_AGENT_DAILY_BUDGET_USD`、既定 5 ドル）。費用が取れない実行は推さず、時間と回数で止める。解くのは本人の「再開」だけ。費用の上限で止めたものは再開できない。
- **知らせ:** 判断が要るときと、そのプロジェクトの列が終わったときだけ LINE へ。ほかは Mac の通知。
- **頼み方:** `node scripts/agent-job.mjs add --project . --request "…" --check "テストが通る=pnpm test" [--artifact "名前=道"] [--review "確認すること"] [--after 番号]`。LINE から仕事を作ることはまだできない（条件のコマンドを走らせるため、入口を手元に限っている）。
- **LINE の言い方:** 「今どうなってる？」「仕事 3 を保留」「仕事 3 を再開」「仕事 3 に指示: …」「仕事 3 を確認した」「仕事 3 を取り消して」「仕事 3 を詳しく」。

## Genie 自身の改善（2026-10-31）

LINE で「Genie を直して: …」と送ると、本体とは別の作業コピー（git worktree）と枝を作り、Claude Code の仕事として進める。
自動の確かめ（変更がある・型・gateway の検査）が通ると、本人に確認を求める。「仕事 N の変更」でファイルと行数を見て、
「仕事 N を取り込む」で手元の元の枝へ merge する。「仕事 N を戻す」で戻せる。

自己改善: 仕事が同じ理由で 7 日に 2 回以上止まっていたら提案する（6 時間ごとに見る。開いた提案は 1 つ、同じ理由は週に 1 回）。
提案だけで勝手に始めない。「改善の提案を進めて」で同じ流れに入る。

- 頼めるのは Claude Code の hooks を登録した本人だけ。`GENIE_IMPROVE_REPO` が無い環境では使えない
- 改善は同時に 1 つ。元は HEAD のコミットなので、未コミットの変更は含まない。作業コピーは別のプロジェクトなので承認ルールを引き継がない
- 検査の削除・`scripts/verify-*`・`memguard`・`.github`・`CLAUDE.md` に触れる変更は LINE から取り込まない
- push しない。再起動もしない（反映は Mac での再起動）。verify-all は通さないので、取り込みの知らせでそう伝える
- まだ無いもの: LINE からの再起動、起動できなかったときの自動の巻き戻し、UI の変更の確かめ

## opencode の見守り: 固まったセッション（2026-10-31）

「作業中」のまま進まないセッションも見分ける。30 分進まなければ本人に 1 回知らせ、60 分進まなければ固まった実行を止めて（abort）「続けて」を送る。
止めるのは 3 回まで。進んでいる間は期限（12 時間）を延ばす（最長 7 日）。進み具合の印は最後の返答の id・部品の数・最後の部品の状態だけで、本文は残さない。
