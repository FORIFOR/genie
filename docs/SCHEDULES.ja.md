# 予約（時間になったら知らせる・頼む）

「明日 9 時に〜教えて」「毎朝 8 時に〜まとめて」と頼むと、Genie はその時間に知らせるか、頼まれたことを始めます。Task Dock、音声、Slack / LINE のどこからでも頼めます。入口は同じ `handleTurn` です。

## 頼み方

| 言い方 | 予約の形 | 時間になったら |
| --- | --- | --- |
| 30分後に会議だって教えて | 1 回 | お知らせ「会議」 |
| 明日9時に資料の準備をリマインドして | 1 回（明日 9:00） | お知らせ「資料の準備」 |
| 金曜の10時に経費精算をリマインドして | 1 回（今週の金曜） | お知らせ |
| 毎朝8時に今日の予定をまとめて | 毎日 8:00 | 仕事「今日の予定をまとめて」 |
| 平日の18時に日報を書くよう知らせて | 平日 18:00 | お知らせ |
| 毎週月曜と木曜の10時に競合のニュースを調べて | 毎週月・木 10:00 | 仕事 |
| 毎月25日の10時に請求書を作って | 毎月 25 日（無い月は月末） | 仕事 |
| 15分おきにメールを確認して | 15 分ごと（5 分より短い間隔は受けない） | 仕事 |

**時間の読み方**

- 「教えて」「知らせて」「リマインドして」「起こして」で終わる頼みはお知らせになり、それ以外は仕事になります。
- 「明日 3 時」「毎日 5 時」のように、日の言葉や繰り返しと一緒に言った 1〜6 時は午後と読みます。日の言葉がないときは、次に来るその時刻にします（10:15 に「9 時に」なら 21:00）。
- 時刻はタイムゾーン（既定は `Asia/Tokyo`、`GENIE_TIMEZONE` で変えられます）の壁時計で持ちます。夏時間がある地域でも、毎日同じ時刻に動きます。

**予約と読まないもの**

時刻のあとに「に」が続き、頼みの形で終わるときだけ予約と読みます。次のような頼みは、いつもの仕事になります。

- 「9 時の会議の資料を作って」
- 「明日の天気を教えて」
- 「毎日のニュースを調べて」

## 作る前に確かめる

予約は黙って作りません。言い直してから「はい / いいえ」を聞きます。

```
あなた: 毎朝8時に今日の予定をまとめて
Genie : 毎日 8:00 に「今日の予定をまとめて」を頼みます。外への送信などは、そのときに承認カードで確かめます。
        次は 10/22（木）8:00、10/23（金）8:00、10/24（土）8:00。
        よろしいですか？（はい / いいえ）
あなた: はい
Genie : 予約しました。次は 10/22（木）8:00 です。「予約の一覧」で確かめられます。
```

- 確かめ中の案は会話ごとに 1 つで、10 分で消えます。
- 予約から始めた仕事も、外への送信・削除・お金などは、そのときに承認カードで確かめます。予約したことは承認の代わりになりません。

## 一覧・止める・取り消す

- 会話で: 「予約の一覧」「予約 2 を取り消して」「さっきの予約を取り消して」「全部の予約を取り消して」。
- HTTP で:
  - `GET /v1/schedules`（`?all=1` で終わったものも）
  - `PATCH /v1/schedules/:id`（`{"status":"paused"|"active"|"cancelled"}`）
  - `GET /v1/schedules/:id/runs`（1 回ごとの記録）

## 時間になったら

- **届け先は頼まれた場所です。**Slack / LINE で頼まれた予約は、同じスレッドへ返します。それ以外は Mac へのお知らせ（`GET /v1/notices`）に残り、Mac が 20 秒ごとに取りに来て macOS の通知に出します。出したものは `POST /v1/notices/ack` で返すので、二度は出ません。通知の許可は、最初のお知らせが来たときに聞きます。
- **仕事の頼みは、Task Dock で頼んだのと同じ入口（`handleTurn`）で、予約の持ち主として頼みます。**予約からの頼みでは予約の言い方を読まないので、予約から予約は作られません。Slack / LINE で頼まれたものは、その仕事の区切り（受付・承認待ち・終わり）もそのスレッドへ返します。

## 守っていること

openclaw の cron を、1 人用に小さくした規則です。

- **見回りは 15 秒ごとです。**Mac が寝ていた間に過ぎた回は、起きたあとの最初の見回りで**1 回だけ**動かし、「〜の予定でしたが、N 分遅れました」と添えます。過ぎた回を全部はやり直しません。
- **1 つの予約で同時に走るのは 1 回だけです。**同じ予定時刻を二度は走らせません（`scheduled_runs` の一意索引）。
- **途中で gateway が落ちた回は、やり直しません。**仕事が二つになるのを防ぐためです。次の見回りで「予約の途中で Genie が止まりました。作業一覧で確かめてください」と知らせます。
- **失敗したときは、間をあけて試し直します**（30 秒、1 分、5 分、15 分、60 分）。繰り返しの予約は 10 回、1 回だけの予約は 3 回続けて失敗したら止め（`disabled`）、そのことを知らせます。
- **実行の結果と、届けた結果は分けて記録します。**届いたか分からない送信は、送り直しません。
- **見回りが要るテナントを探すときだけ、テナントを跨ぎます。**このとき `astra_identity` で読めるのは「いつ・どのテナントか」の列だけで、頼みの中身は読めません。

## 制限（未実装・未検証）

- **見回りは gateway の中で動きます。**gateway が止まっている間（Mac の電源が切れているなど）は動かず、起動したあとで 1 回だけ追いつきます。スリープ中の Mac を、予約の時刻に起こすことはしません。
- Mac では作業一覧の上に「予約」として出し、止める・再開・取り消すができます（予約があるときだけ。DESIGN.md §8.2）。作るのは会話だけです。
- **時刻は日本語の決まった言い方だけを読みます。**読めない言い方は、いつもの仕事になります。
- **実際の Slack / LINE と macOS の通知では、まだ確かめていません。**通知は Swift の単体テストで、お知らせの読み取りだけを確かめています。
