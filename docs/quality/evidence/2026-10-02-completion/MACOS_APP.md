## Exit-observation failure and correction

The initial suite after the model propagation change was **30 passed, 1 failed**. Its real TERM-resistant child case failed with the ownership-change error. The original [failure log](model-propagation-tests.log) is retained.

A lightweight reproduction spawned only its own tiny Node children. On all five runs, a single `ps` snapshot observed the same PID and start time transition from `S` with full argv to `?E` with `(node)`. The old exact-argv comparison rejected this legitimate exit transition. The local macOS `ps(1)` manual defines the additional `E` flag as “trying to exit” and primary `Z` as dead/zombie. Exit-in-progress is therefore not treated as success.

The correction adds state to the same snapshot and checks PID/start before considering it. It accepts only disappearance or matching dead/zombie state as completion; exit-in-progress remains bounded by the existing wait. No extra TERM/KILL is sent after argv is discarded in that state. A return to a live state with changed argv is rejected, as are different PID/start values even when marked zombie. Startup does not claim an already exiting/dead app as its running instance.

Final command: `node --test scripts/tests/managed-local-preview.test.mjs`. Result: **32 passed, 0 failed, 0 skipped, exit 0** in the [complete log](model-propagation-fixed-tests.log). Prettier and `git diff --check` passed. These tests launch harmless owned fixture processes; they do not start Genie, a VM, Ollama, or a model request. A transient zsh wrapper error while collecting an earlier successful test summary was corrected; the linked final run captures the actual exit code.
