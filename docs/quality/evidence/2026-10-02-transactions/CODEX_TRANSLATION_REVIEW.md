## Follow-up source review after corrections

The implementation owner then reported a stable revision. `/root/verification_audit` reread it without building, testing, or operating the UI. Fresh file hashes are in [codex-translation-review-followup.json](codex-translation-review-followup.json). Root's serial focused tests were in progress; this section does not pre-empt their outcome.

- **CT-5 resolved in source:** the same resolved and login-probed absolute CLI path now reaches both the host `runtimeEnv` and the native app `appEnv`. The host already consumes `ASTRA_CODEX_PATH`.
- **CT-6 resolved in source for normal Quit and a responsive app receiving SIGTERM:** normal exit returns `terminateLater`, resets translation, closes the shared permit to new requests, cancels registered owned processes, and waits for the active operation and its deferred context deletion before replying. Managed-launcher SIGTERM is caught by a retained dispatch signal source and routed into that same exit path. External termination does not wait for a recording-confirmation dialog. Repeated termination is guarded.
- The signal override is installed after both selftest and native-messaging early-return paths, preserving their prior headless termination behavior. A caught no-op is used instead of `SIG_IGN`, so the ignored disposition is not intentionally inherited by exec'd CLI children. The added fixture test recreates the caught-parent condition and checks that ordinary child termination does not require the two-second KILL escalation.
- **CT-4 now has meaningful tests, outcome separate:** tests execute a harmless Node fixture through the real Process runner for active cancellation, timeout, output cap, closed input, ignored TERM, and inherited signal handling. They verify the owned PID has exited, private context is deleted, and a later translation can acquire the permit. The irreversible app-scope shutdown test is isolated behind an explicit opt-in and is intended to run alone in a fresh test process.

No additional P1 source finding remains in this correction review. This is not an actual managed-app SIGTERM-during-translation E2E result. Cleanup depends on a responsive parent event loop; SIGKILL, a parent crash, or an application hang is outside the demonstrated guarantee. The implementation retains its external model, provider disclosure, transcript-only stdin, disabled tools, bounded output, one active request, and no automatic API/local fallback. Translation quality under real meeting content and the final whole-product gate remain unverified.
