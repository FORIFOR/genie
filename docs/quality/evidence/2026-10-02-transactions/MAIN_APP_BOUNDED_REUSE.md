## External provider cross-check

The dedicated host registered only `models: ["codex"]`. While it was still running, its exact owned process (PID 54174) had `ASTRA_LLM_CLI=codex`, `ASTRA_CODEX_MODEL=gpt-6-sol`, the dedicated data root and Gateway, and `ASTRA_COMPUTER_VISION_EXTERNAL=on`. The app had `ASTRA_LLM_CLI=codex`, `ASTRA_LOCAL_VISION=0`, and the OpenAI disclosure. Existing host code restricts available kinds to that configured provider; there is no local fallback in this route. These observations and the persisted app result corroborate the selected app → Gateway → host route. The task API does not expose a per-generation upstream provider receipt or echoed model identifier, so the exact model identity is configuration evidence rather than an independently returned upstream receipt.

The memo test sent only the fictional text. The transaction simulator is a deterministic, registered native adapter: it locates the exact quote-bound AX button and reads a local receipt. It does not ask a model to interpret the simulator or send its image externally. Its native target dialog still says `このMacのモデル`; that phrase is imprecise for this model-free simulated path and is not evidence that the external text route fell back to Qwen. No arbitrary website checkout or external screenshot-model action was tested here.

## Limits and prior failures

The earlier [fixture exit](FIXTURE_SESSION_EXIT.md) and its separate in-flight stop → `FAILED` observation remain historical failures. This later run establishes main-app reuse while the owned window remained alive. Declining the third request **before dispatch** does not verify the pending fix for an already-running task's cancellation race. Root stopped this dedicated preview around 17:10Z after these observations; the follow-up verifier stopped polling then.

No real merchant/broker, delivery, payment, stock trade, native five-minute idle wait, human concurrent keyboard/IME work, arbitrary-site model planning, fresh full-product gate, commit or push is covered. The fixture still requires fresh target consent after its owned window/session is closed or expires.
