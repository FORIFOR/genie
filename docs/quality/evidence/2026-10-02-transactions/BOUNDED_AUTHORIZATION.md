Quota is a conservative reservation, not a count of successfully delivered orders: **unknown results, cancellation, failure, and even failures before submission do not restore it**. An order outside the grant or after its quota is exhausted can still request a new one-order human approval. The grant API is not an agent tool. Native consent remains separately enforced.

## Review corrections and limits

Independent reviewer `/root/verification_audit` identified that a completed task could prevent recovery of a committed creation receipt. The core now checks immutable request identity before interpreting the task's current state; the ledger tests preserve that regression. `/root/computer_correctness` independently found the corresponding API-side P2: a running task with a revoked grant returned an error before its receipt-only path. Root moved the non-waiting path before grant validation and added the HTTP regression. The final static review found no additional P1 in the API/activity/proof scope reviewed; this is not a guarantee that no defects exist.

The backend tests used the dedicated `genie-transactions-20261002` PostgreSQL test container on `127.0.0.1:32768`; the wrapper created and removed disposable databases. Production/preview order data was not used. The actual worker proof-chain test does not run the host input loop, a merchant adapter, AppKit, or an external provider. The host's revocation propagation remains cooperative (500 ms polling, bounded authority-request timeout), not instantaneous external-order cancellation.

Live providers remain unregistered/unsupported, and stock coverage is paper simulation only. Deduplication is by the explicit business key, not semantic recognition of arbitrary repeated natural-language requests. UI understanding, persistent native consent reuse, real checkout completion, and external service compatibility remain outside this document. No commit or push was made by this evidence task.
