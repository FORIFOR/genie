仕様 v1.0（本人から）は Python（FastAPI・LangGraph）の新規構成を例にしているが、Genie は TypeScript（Fastify・Temporal・Postgres）で、

## 2. 最初のリリースで達成する状態（仕様 §11）と、作るもの

> 「明日の予定を教えて」→ 予定 →「午後にずらして」→ 変更案 → 承認 → 変更 →「やっぱり元に戻して」→ 元に戻る。
> 領収書の写真 → 金額と日付を確かめ → 家計簿に。失敗しても完了と偽らず、やり直させない。

ほかの項目は、W1〜W6 のあとに回す。

- **Jev:** W2・W3 の振り分けの口（`IntentClassifier`）に差し込める形にしておき、つなぐ先が決まったら入れる。
- **リッチメニュー・LIFF:** LINE Developers での登録と、公開の置き場所（ホスティング）が要るので、決めてから。

## 3. 順番と合格条件

W1 → W2 → W3 → W4 → W5 → W6。どれも、`evals/line-conversation` を回して基準値から下がらないこと、狙った数字が上がることを確かめてから入れる。

最初のリリースの条件:

- 評価で、してはいけないことを 0 件、完了と偽った答えを 0 件にする。
- 承認なしの送信・変更を 0 件にする。
- 二重実行を 0 件にする。
- §2 の 2 つの流れが、結合試験（偽の Calendar）と実機（本人の LINE）で通る。

## 4. 本人に決めてもらうこと

- **Jev:** どこで動いていて、どう呼ぶか。
- **Google カレンダーの書き込み:** 予定の変更・削除には `calendar.events` の許可が要る。いまの接続で許可していなければ、つなぎ直しが要る。
- **リッチメニュー・LIFF:** やるかどうか、いつやるか。公開の置き場所が要る。

## 5. 進み（2026-10-27）

| #   | 状態               | 何をしたか                                                                                                                                                                                                                                                                                                                                                                                                                     |
| --- | ------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| W1  | 済                 | 汎用の答えの指示に「あなたは何も実行していない」を明記。送る前に「入れました」「送りました」「確認なしで行います」などの主張を探し、あれば「まだ実行していません」に差し替える（`workers/agent-host/src/action-claims.ts`）。評価: 完了と偽った答え 2.6% → **0%**                                                                                                                                                              |
| W2  | 済                 | 直前の会話（最大 6 発話・1,500 字）を汎用の答えに渡す（`turn.ts` の `historyOf` → `general-executor` → `llm.answer`）。LINE で返した答えも会話に残す（`channels` の `remember`）。直前の会話があれば、会話と調べものでは「それ」を聞き返さずに話の流れで解かせる                                                                                                                                                               |
| W3  | 済（実機は未確認） | 「明日の予定」→ `calendar.agenda`（端末の Google カレンダーを読む・一覧を JSON で残す）、「午後にずらして」「30分遅らせて」「15時の会議を…」→ 直前の一覧から対象を選び `calendar.move`（変更前・後を見せる承認カード → 端末で変更・変更前を返す）、「元に戻して」→ 直前の変更を入れ替えた `calendar.move`（これも承認）。対象が 2 つ以上・一覧が無いときは聞き返す。予定を入れる頼みを予約にしない・来年の天気を取りに行かない |
| W4  | 済                 | 確かめ中（「家計簿に付けますか？」「カレンダーに入れますか？」）を DB に（`pending_confirmations`、会話に 1 つ・10 分）。再起動しても「はい」が効く。確かめ中に「修正する」「金額は1280円」「日付は昨日」「費目は外食」「店はローソン」で直してから付けられる。LINE では文の終わりの「はい / 修正する / いいえ」をタップで送れるボタン（Quick Reply）にする（承認ボタンがあるときは足さない）                                  |
| W5  | 済                 | 一度に頼まれた複数のことを分ける（`conversation/src/split.ts`: 「あと」「それと」「ついでに」が文の切れ目にあるとき・「予定と天気とニュース」）。LINE では 1 つずつ同じ入口に通し、済んだことと要ること（「レシートの写真を送ってください」）を 1 通で返し、仕事になったものは終わったら本文で返す。確かめ中への返事・物の名前の続きは分けない。「買い物リストに卵と牛乳」「TODOに区役所で住民票」も届くように                 |
